Ejecuta el flujo web completo para: $ARGUMENTS

Reglas:

1. Trata la petición como una idea, no como un brief. No pidas framework, paleta,
   tipografías ni arquitectura: decide tú y declara supuestos en una línea.
2. Inspecciona el proyecto antes de cambiar nada; respeta lo que ya funciona.
3. Carga `web-premium` para el orden de fases y `web-art-direction` para
   identidad, tipografía, composición, movimiento y crítica visual. Carga
   `impeccable` solo en crítica/pulido y Playwright/Chrome DevTools para verificar.
4. Delega con criterio, no por rutina: `studio-director` si necesitas direcciones
   de arte distintas; `studio-builder` para implementar; `studio-engineer` solo
   para problemas técnicos difíciles; `studio-critic` una vez al final.
5. Construye una primera versión funcional antes de refinar. Itera solo sobre
   problemas observados; evita bucles infinitos.
6. Verifica en navegador real a 390/768/1440/1920 px, consola limpia, teclado y
   foco. Si no puedes comprobar algo, dilo con el motivo.
7. No inventes reseñas, clientes, premios ni métricas. Marca el contenido
   provisional.
8. No instales dependencias innecesarias, no despliegues, no publiques y no hagas
   pagos sin autorización explícita.
9. Entrega un resumen breve: concepto, decisiones clave, qué probaste y límites.
